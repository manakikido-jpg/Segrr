# Segrr デザイン依頼プロンプト

別セッションでデザインを作成するためのプロンプト。以下をそのまま貼って使う。
デザイン確定後、`:root` のCSS変数(デザイントークン)だけを受け取れば、A3のUIコンポーネントに後から適用できる。

---

Segrr という業務ツールのUIをデザインしてください。デザインキャンバスとして作成し、各画面を1つのアートボードにしてください。

## プロダクト

個人事業主・フリーランス向けの書類管理ツール。見積書→契約書→請求書という一連の書類を、データを再入力せずに引き継いで作成・管理する。顧客管理と案件の進捗管理も含む。

- 利用者: 個人事業主本人(1日に何度も開く。仕事道具として毎日使う)
- 主にPCで作成、スマホでは閲覧と簡単な入力
- 日本語UI。日本の商習慣(消費税・インボイス制度・源泉徴収)に沿う

## トーン

- **装飾より情報密度。** 一般消費者向けアプリではなく、毎日開く業務ツール。余白で情報を減らすより、一覧性を優先する
- **金額が主役。** 数字は等幅で右揃え、桁区切りあり。金額の大小がひと目で比較できること
- **静か。** 彩度の高い色は、ステータスと警告にだけ使う。それ以外はグレースケールに近い
- ライトモードを主、ダークモードも定義する

## デザインしてほしい画面(アートボード)

### 1. ログイン
Googleアカウントでログインするだけの画面。招待されていないアカウントを拒否したときのエラー表示も含める。

### 2. ダッシュボード
案件ステータス別の件数サマリ、今月の請求額、期限が近い/超過している書類のリスト。

### 3. 顧客一覧 / 4. 顧客詳細・編集
一覧は検索とテーブル。詳細はその顧客の案件一覧を含む。

### 5. 案件一覧
### 6. 案件詳細(この画面が最重要)
1つの案件について、**見積 → 契約 → 請求 の流れを縦のタイムラインで見せる**。各書類のカードにはステータス・金額・日付を表示し、次に取るべきアクションのボタンを置く(例: 見積カードに「この見積から契約書を作成」、契約カードに「この契約から請求書を作成」)。分割請求のため、契約カードの下には請求書が複数ぶら下がり、契約金額に対する請求済み・残額を表示する。まだ存在しない書類は空のプレースホルダとして道筋を示す。

### 7. 見積書 作成・編集フォーム(2番目に重要)
画面の中心は**明細行エディタ**。各行のカラムは:

| 品名 | 説明 | 数量 | 単価(税抜) | 税率 | 金額 |
|---|---|---|---|---|---|
| 入力 | 入力 | 数値 | 数値 | 10% / 8% の選択 | **自動計算・編集不可** |

行の追加・削除・ドラッグでの並び替えができること。スマホでは表が横スクロールではなく、1行=1カードに折り返す形も設計してください。

フォーム下部の**金額サマリ**は必ず以下を全部表示します(適格請求書の要件):

```
10%対象      小計 ¥1,000    消費税 ¥100
8%対象       小計 ¥999      消費税 ¥79
─────────────────────────────
税抜合計                    ¥1,999
消費税合計                  ¥179
合計(税込)                 ¥2,178
```

### 8. 見積書 詳細(閲覧)
### 9. 契約書 作成・編集(見積からの変換画面を含む)
見積から変換するとき、「どの見積から引き継いだか」が分かる表示を入れてください。

### 10. 請求書 作成・編集(分割請求)
見積・契約と同じ明細行エディタに加えて:
- **契約に対する残額の表示**(契約金額 ¥1,000,000 / 請求済み ¥600,000 / 残額 ¥400,000)
- 残額を超えて入力したときのエラー表示
- **源泉徴収のON/OFF**と、ONのときの金額サマリ:
```
合計(税込)                 ¥1,100,000
源泉徴収税額               -¥102,100
─────────────────────────────
差引請求額                  ¥997,900
```

### 11. 書類一覧(見積・契約・請求で共通のレイアウト)
ステータスで絞り込めるテーブル。

### 12. 設定
自社情報(名称・住所・電話・振込先)、適格請求書発行事業者の登録番号、消費税の端数処理(切り捨て/四捨五入/切り上げ)。**登録番号は未取得(免税事業者)でも使えるので、空欄が異常に見えない設計**にしてください。

## 必ず設計してほしい状態(ステート)

1. **ステータスバッジ** — 見積: 下書き / 送付済 / 承認済 / 却下、契約: 下書き / 送付済 / 締結済 / キャンセル、請求: 下書き / 送付済 / 入金済 / キャンセル。加えて日付から算出される **期限切れ**(見積の有効期限切れ、請求の支払期限超過)を、上のステータスに重ねて表示する形
2. **編集ロック** — 契約に変換された見積、請求書が発行された契約は編集できません。「なぜ編集できないか」と「代わりに何をすればいいか(複製して新規作成)」が分かる表示にしてください。グレーアウトするだけにしない
3. **金額超過エラー** — 分割請求の合計が契約金額を超えたときの表示
4. **空状態** — 顧客ゼロ / 案件ゼロ / 書類ゼロのとき
5. **明細0行** のときの見積フォーム

## 共通パーツ

サイドナビ(ダッシュボード・顧客・案件・見積・契約・請求・設定)、ボタン(主/副/危険)、テキスト入力、セレクト、日付入力、テーブル、ステータスバッジ、金額サマリ、モーダル、トースト、エラーメッセージ。スマホ幅でのナビの畳み方も設計してください。

## 対象外

PDF帳票(見積書・請求書のA4レイアウト)は別途実装するので、このデザインには含めなくて構いません。

## 成果物

各画面のアートボードに加えて、**デザイントークンを1枚のアートボードにまとめてください**。色・フォントサイズ・行間・余白・角丸・影を、CSS変数として実装側がそのままコピーできる形(`--color-bg`, `--space-4` のような命名)で並べてください。ライトとダークの両方の値を含めてください。
